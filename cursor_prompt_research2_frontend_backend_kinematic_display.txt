请你作为代码修改助手，继续完善“基于普通视频的网球动作分析系统”的研究二功能。本轮是第三步：在前两步已经扩展了球拍/人体采集维度，并将角度特征用于四类动作切分之后，把新增的运动学分析结果接入现有后端产物和前端展示。

本轮重点：

1. 不重做整个系统。
2. 不重新设计首页、导航、上传流程和 API 路由。
3. 在现有正手、反手、发球、截击页面中，增量展示新增运动学分析结果。
4. 后端增加运动学摘要 CSV、运动学图表等产物。
5. 前端在原有结果区增加“运动学摘要”“角度曲线”“指标下载”等模块。

一句话原则：

在现有系统上“长出”运动学分析展示，不要把前端改成一个全新的 dashboard。

一、项目当前结构

系统已有流程大致为：

上传视频
→ YOLO 球拍关键点追踪
→ RTMPose 人体姿态估计
→ segmentation.py 自动切分
→ 输出 CSV、PNG、MP4
→ FastAPI 返回 artifacts
→ Vue 静态页面展示结果

四类动作：

- forehand 正手
- backhand 反手
- serve 发球
- volley 截击

已有前端页面通常包括：

- 首页
- forehand.html

- volley.html

已有后端产物 kind 可能包括：

这些已有字段、kind 和展示逻辑必须保留。

六、四类动作展示差异

前端可以共用一套展示逻辑，但每类动作的标题和重点指标略有不同。

正手 forehand：

- 重点显示：拍头速度峰值、持拍侧肘角变化、持拍侧膝角变化、肩髋角变化、拍头-手腕距离。

反手 backhand：

- 重点显示：拍头速度峰值、肩髋角变化、侧身/肩部变化、横向挥拍幅度、支撑腿膝角变化。

发球 serve：

- 重点显示：抛球时间、挠背时间、击球时间、抛球高度差、挠背深度、拍头速度峰值、肩角/肘角/膝角变化。

截击 volley：

- 重点显示：速度突刺、动作时长、拍头相对手腕高度、肘角稳定性、肩髋角变化小、轨迹紧凑程度。

如果前端暂时只做通用表格，也可以先不做四类动作差异化布局。

七、重要术语

页面或图表中建议使用：

- 运动学分析
- 图像平面角度
- 拍头速度
- 球拍姿态
- 人拍相对关系
- 肩髋分离角
- 持拍侧肘角
- 持拍侧膝角

不要使用：

- 动力学分析
- 关节力矩
- 肌肉力
- 地面反作用力
- 真实 3D 关节角

除非该页面明确展示的是研究三 OptiTrack + 测力台 + OpenSim 结果。本系统当前研究二前端展示应叫“2D 运动学分析”，不要叫“动力学分析”。

八、CSV 读取与前端兼容

如果前端读取 summary CSV：

1. 优先使用已有的文件下载接口获取 CSV。
2. 前端用简单 CSV parser 即可。
3. 如果项目已有 CSV 解析工具，复用现有工具。
4. 如果没有，可以实现一个轻量解析函数。
5. CSV 中空值、NaN、None、空字符串要显示为 “-”。
6. 不要因为某列缺失导致整个表格不显示。

表格列可以用字段存在性判断：

- 字段存在则显示。
- 字段不存在则跳过或显示 “-”。

九、后端 summary 生成建议

请在每个 segmentation.py 中或公共 helper 中新增：

- build_kinematic_summary(...)
- save_kinematic_summary_csv(...)
- plot_upper_limb_angles(...)
- plot_lower_limb_angles(...)
- plot_trunk_rotation(...)
- plot_racket_kinematics(...)

如果四类动作代码重复较多，可以抽公共函数；但不要为了抽象大规模重构。

summary 统计规则：

1. 对每个切分片段，在 start_frame 到 end_frame 范围内统计。
2. contact/hit 帧优先使用算法已有的 contact_idx/hit_idx。
3. 速度峰值取片段内 racket_head_speed 最大值。
4. 角度 range = max - min，忽略 NaN。
5. at_contact 类指标取 contact/hit 帧附近最近有效值。
6. 若字段不存在，填 NaN。
